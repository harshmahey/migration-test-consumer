# Migrate to PaymentsAPI v2.0.0

The PaymentsAPI has introduced breaking changes that require updates to the migration-test-consumer application. Key changes include renaming fields in both request and response structures.

## Steps

### 1. Update CreatePaymentRequest field (automatable)

The field `customer_id` in the CreatePaymentRequest has been renamed to `customer.id`. Update the request structure accordingly.

**Before:**

```
const request = { customer_id: '12345' };
```

**After:**

```
const request = { customer: { id: '12345' } };
```


### 2. Update PaymentResponse field (automatable)

The field `customer_id` in the PaymentResponse has been renamed to `customer.id`. Update the response handling to reflect this change.

**Before:**

```
const customerId = response.customer_id;
```

**After:**

```
const customerId = response.customer.id;
```


### 3. Update query parameter for payments list (automatable)

The query parameter `customer_id` for the payments list endpoint has been renamed to `customer.id`. Update the API call to use the new parameter name.

**Before:**

```
const response = await fetch('/v1/payments?customer_id=12345');
```

**After:**

```
const response = await fetch('/v1/payments?customer.id=12345');
```


## Estimated effort

8 hours

## Risks

- Potential for missed updates if all instances of the old field names are not replaced.
- Changes may introduce bugs if not properly tested.
- Existing tests may need to be updated to reflect the new API structure.
